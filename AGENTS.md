# Working in this repository

Modwerk builds custom firmware modules for Elektron instruments. This repository holds the module SDKs (`sdk/`), a React and Vite site (`src/`) and a Cloudflare Worker API (`server/`, `worker.ts`).

- Use Node 24 (`.nvmrc`), then `npm ci`.
- Before each commit run `npm run check -- --base origin/main`. Documentation/media/prose-only edits use the lightweight catalogue, licence and capture-provenance checks; source or behaviour changes run the full app suite. Regenerate changed catalogues first. Native compilation is required only when firmware source or build inputs change. Do not repeat full checks or native builds for documentation updates.
- To add, port or update a module, follow [docs/ADD_A_MODULE.md](docs/ADD_A_MODULE.md). Every new module version requires written, version-matched release notes in `src/community/module-changelogs.json`; preserve previous entries and describe the actual changes and limitations. `npm run check` enforces this on every validation path.
- Before you write a module, read [docs/module-guides/README.md](docs/module-guides/README.md) and the guide for its category (effects, machines, playback, scenes, midi-usb, system, standalone). Anything that acts in time follows [sequencing.md](docs/module-guides/sequencing.md): use the instrument's own tempo, track speed and swing, never a clock of your own. Run `npm run module:doctor -- <id>` until it is green.
- Before writing or changing Octatrack DSP or ColdFire code, read the traps in [sdk/octabam/AGENTS.md](sdk/octabam/AGENTS.md). That is octabam's own file, kept unchanged because its code cites it. Its `make` commands describe upstream octabam, not this repository; build and check with the commands in the guide.
- Module creators can add, replace or remove their own Ko-fi support link from a claimed module in the Developer workspace. Module pages show a small cup beside the creator name; clicking it loads the embedded tip dialog. Preserve this flow, per-module ownership checks and the matching frame policies in `vite.config.ts` and `public/_headers`. See [creator support](docs/APP_DEVELOPMENT.md#module-creator-support) and [developer ownership](docs/DEVELOPER_WORKSPACE.md).
- For app and backend work, see [docs/APP_DEVELOPMENT.md](docs/APP_DEVELOPMENT.md).
- Never commit firmware, extracted stock code or tables, memory dumps or built images. Firmware stays on the developer's computer and never enters CI.
- Do not edit generated files by hand: `src/catalog/module-documents.json`, `src/catalog/compatibility-checks.json`, the licence notices and the machine registry. `npm run modules:generate`, `licenses:generate` and `machines:generate` write them.
- Work on a branch off current `main`. Open a pull request for each separate piece of work without being asked: commit, push and run `gh pr create` before you report it as done. Follow-up edits to work that already has an open pull request go on that pull request's branch as further commits, not a new one. The owner merges. Keep unrelated changes out of the diff.
